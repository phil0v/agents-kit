# Delta dispatch

Delta dispatches through its subthread spawn API with a profile selected by role. Use `worker` for the worker, `reviewer` for the four inspector roles, and `scout` for the tool-runner. The adapter mechanism was verified against Delta 0.27.2. Subagent profiles are settings-backed under the `/subagents/profiles` settings path. Delta loads no package forms for this package. The built-in ids are `worker`, `scout`, and `reviewer`. Sparse overrides carry `description`, `worktree`, `prompt`, `system_prompt`, `model`, `thinking`, and per-provider `overrides`. Dispatch is `spawn_subthread` naming that profile. A model argument is `provider/model-id` with an optional `[effort=<level>]` suffix. Its supported levels come from the runtime model listing, never assumption. Delta grants tools by profile kind, not per-role lists. The mapping's declared tools are the capability checklist, verified against the spawned profile's actual grants. A spawned agent's self-reported profile name is not loaded-profile evidence. A `scout`-kind tool-runner reaches file writes through its terminal. Worker spawns run in isolated Delta worktrees. They hand back unmerged changes for the coordinator to merge and hash-verify. Inspectors judge the repository of record under the replica rules in Role resources in `<package>/references/dispatch.md`. A Delta build without profile selection is an unverified or blocked dispatch. So is a model whose listed levels exclude a requested effort. Neither is a silent default.

After an isolated Delta worker returns, the coordinator pulls the worktree with `merge_worktrees`. The coordinator then runs `git add` on the assigned paths. Next, it reads `git status --porcelain` again and compares the returned hashes with the files. A dispatch to an isolated worker tells the worker to run `git add` on each new file. The mapped `glob` tool for Delta (see the `tool_names` table of `<package>/harnesses/mapping.json` for the tool name) lists one directory level and accepts no pattern.
